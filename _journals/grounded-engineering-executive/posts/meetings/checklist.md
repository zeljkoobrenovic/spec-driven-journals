*The working checklist behind this principle, grouped from foundations through the core cadence to the shared quality bar. The Article tab carries the rationale, implications, and anti-patterns.*

### Foundations: Why You're Running Meetings

- [ ] Clear purpose for each meeting (decision, review, development, alignment, Q&A).
- [ ] Meetings fill communication gaps (do not default to them).
- [ ] Used to:
  - [ ] Distribute context
  - [ ] Communicate culture
  - [ ] Surface concerns
- [ ] Willing to iterate, pause, or cancel low-value meetings.

### Core Meeting Cadence

**Weekly Team Meetings**

- [ ] Each manager meets weekly with their direct team.
- [ ] Clear agenda.
- [ ] Focused on execution and alignment.
- [ ] Tight, well-run, and ends on time.

**Weekly Engineering Leadership Meeting**

- [ ] Includes all direct reports.
- [ ] May include Recruiting, People, and Finance partners.
- [ ] Running, shared agenda doc.
- [ ] Prioritized topics before the meeting starts.
- [ ] Used as a working session (not status theater).
- [ ] Builds "first team" mindset among leaders.
- [ ] Meets weekly (unless org is very small).

**Weekly Tech Spec Review**

- [ ] Anchored to a concise written document.
- [ ] Reading is a prerequisite (or reading time built in).
- [ ] Discussion-driven (not the author presenting slides).
- [ ] Feedback-centered.
- [ ] Clear process for getting specs scheduled.
- [ ] Dedicated meeting owner.
- [ ] First-time facilitators get a practice run.

**Weekly Incident Review**

- [ ] Anchored to the written incident write-up.
- [ ] Focus on learning, not blame.
- [ ] Discussion over the presentation.
- [ ] Clear scheduling process.
- [ ] Owned by a responsible leader.
- [ ] Attendance by senior engineering leadership.

**Monthly Engineering Managers Meeting**

- [ ] All engineering managers attend.
- [ ] Format:
  - [ ] 1-minute updates (working on / excited about / worried about)
  - [ ] Development topic presentation (~30 min)
  - [ ] Open Q&A
- [ ] Focused on craft and leadership development.
- [ ] Adjusted for pressing issues when needed.

**Monthly Staff+ Engineers Meeting**

- [ ] All Staff+ engineers attend.
- [ ] Similar development format as managers session.
- [ ] Managers generally excluded.
- [ ] Focused on technical leadership growth.

**Monthly Engineering Q&A**

- [ ] 60 minutes.
- [ ] Start with new hire intros.
- [ ] Short intro message from Head of Eng.
- [ ] The majority of the time is reserved for Q&A.
- [ ] "No questions off limits" tone.
- [ ] Tool supports:
  - [ ] Pre-submitted questions
  - [ ] Upvoting
  - [ ] Anonymous questions
- [ ] Reminder sent 1 hour before the session.
- [ ] Rotate times across time zones if needed.
- [ ] Avoid recording (unless necessary).
- [ ] Use to:
  - [ ] Surface concerns
  - [ ] Test trust
  - [ ] Highlight contributors

### Additional High-Value Meetings

**1:1 Meetings**

- [ ] Weekly with direct reports.
- [ ] Regular cadence with key peers.
- [ ] Flexible duration (30–60 mins).
- [ ] Focused on support, growth, and alignment.

**Skip-Level Meetings**

- [ ] Fixed time budget (e.g., 1–2 hrs/week).
- [ ] Structured format (group or 1:1).
- [ ] Don't crowd out core work.

**Execution Review (Cross-Functional)**

- [ ] Weekly or monthly cadence.
- [ ] Tracks execution and resolves blockers.
- [ ] Cross-functional (not Eng-only).
- [ ] Clear owners and follow-ups.

**Show-and-Tells / Demos**

- [ ] Regular cadence (weekly–monthly).
- [ ] Celebrate work.
- [ ] Reinforce culture and values.

**Tech Talks / Learning Sessions**

- [ ] Reading groups or knowledge sharing.
- [ ] Encourages collective learning.

**Engineering All-Hands**

- [ ] Clear format (roadmap/demo/culture).
- [ ] Aligned with company-wide meetings.
- [ ] Not duplicative of the company all-hands.

### Scaling Guidelines

- [ ] Split meetings when participant context diverges.
- [ ] Keep developmental sessions ≤10 active participants.
- [ ] Push meetings down a layer if the org grows too large.
- [ ] Maintain org-wide Q&A as a single shared forum.
- [ ] Don't split prematurely due to 1–2 difficult participants.
- [ ] Hold participants accountable for behavior.
- [ ] Optimize for engagement, not headcount.

### Ownership & Leadership

- [ ] Clear the meeting owner for each recurring session.
- [ ] The leader shows up consistently.
- [ ] Executive models behavior expected from others.
- [ ] Coordination support (EA/program manager).
- [ ] Even if not leading, the executive remains accountable for quality.

### Quality Bar

- For every meeting, ask:

- [ ] Is it anchored to a written document?
- [ ] Is discussion prioritized over presentation?
- [ ] Are the right people in the room?
- [ ] Is there a clear output (decision, alignment, learning)?
- [ ] Would we cancel this if it stopped adding value?
