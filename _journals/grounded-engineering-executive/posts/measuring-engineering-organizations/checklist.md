*The working checklist behind this principle, grouped by audience first — yourself, then each stakeholder class — followed by sequencing, antipatterns, and data confidence. The Article tab carries the rationale, implications, and anti-patterns.*

### Measure for Yourself (Internal Leadership)

**Measure to Plan**

- [ ] Maintain a single view of Business, Product, and Engineering impact.
- [ ] Track shipped projects by team.
- [ ] Track the impact of each shipped project.
- [ ] Use metrics to support prioritization (not just delivery mechanics).

**Measure to Operate**

- [ ] Track incident count (with review writeups).
- [ ] Track user-facing downtime.
- [ ] Track API / website latency.
- [ ] Track engineering cost normalized to a core business metric.
- [ ] Track user ratings (e.g., app store ratings).
- [ ] Track onboarding conversion completion rate.
- [ ] Review operational metrics regularly.

**Measure to Optimize**

- [ ] Track delivery lead time.
- [ ] Track deployment frequency.
- [ ] Measure developer productivity (e.g., survey or framework like SPACE).
- [ ] Instrument feedback loops within engineering.
- [ ] Use metrics to improve the system, not judge individuals.

**Measure to Inspire & Communicate**

- [ ] Maintain a list of transformational technical investments.
- [ ] Highlight generational improvements at company meetings.
- [ ] Include at least one meaningful infrastructure improvement in annual planning.
- [ ] Communicate the business impact of engineering work.

### Measure for Stakeholders

**Measure for CEO / Board**

- [ ] Define a clear goal aligned to the business strategy.
- [ ] Share progress updates against that goal.
- [ ] Reuse planning/operational metrics where possible.
- [ ] Focus on business impact, not micro-optimization.
- [ ] Avoid presenting optimization metrics as proof of impact.

**Measure for Finance**

- [ ] Track actual vs budgeted headcount.
- [ ] Track actual vs budgeted vendor costs.
- [ ] Document capitalizable vs expensed engineering work.
- [ ] Align on investment thesis and capacity allocation.
- [ ] Document cost allocation methodology across initiatives.

**Measure for Strategic Peer Organizations (Product, Design, Sales)**

- [ ] Align on shared business outcomes.
- [ ] Use planning impact metrics to support collaboration.
- [ ] Ensure engineering measurement supports cross-functional goals.

**Measure for Tactical Peer Organizations (Customer Success, Legal, etc.)**

- [ ] Agree on concrete measurable outcomes.
- [ ] Track shared operational metrics (e.g., resolution time, ticket acceptance).
- [ ] Establish regular review cadence.
- [ ] Adjust metrics as cross-functional needs evolve.

### Sequence Your Measurement Work

- [ ] Only measure what you'll use in decision-making.
- [ ] Measure some easy things to build trust.
- [ ] Take on one new measurement initiative at a time.
- [ ] Establish a baseline across major measurement categories.
- [ ] Iterate and refine over time.

### Avoid Measurement Antipatterns

- [ ] Don't substitute metrics for trust-building.
- [ ] Don't wait for perfect data before measuring.
- [ ] Don't use optimization metrics to judge performance.
- [ ] Don't measure individuals instead of teams.
- [ ] Don't over-worry about potential misuse of data.
- [ ] Don't decide measurement strategy in isolation.

### Build Confidence in Data

- [ ] Review data weekly.
- [ ] Compare trends month-over-month or quarter-over-quarter.
- [ ] Maintain explicit hypotheses about metric behavior.
- [ ] Investigate when data contradicts expectations.
- [ ] Review data collaboratively (not alone).
- [ ] Segment data to uncover hidden issues.
- [ ] Compare objective metrics to subjective experience.
- [ ] Document open questions and follow-ups.

### Ongoing Mindset

- [ ] Measure something (avoid measuring nothing).
- [ ] Iterate in small steps.
- [ ] Focus on usefulness over perfection.
- [ ] Treat measurement as an evolving process.
