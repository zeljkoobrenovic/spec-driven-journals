## Company scale

- 2015: **two services** — Dispatch (Node.js; rider/driver traffic, ~4-second ping protocol returning the whole state) and API (Python; post-trip: payments, receipts) [POD].
- ~600 engineers when Medisetty joined in 2015; marketplace team ~50–60 [POD].
- Grew to "order of thousands" of services; ~2018–2019 standardized on **Go and Java** [POD]. Host's outro [HOST]: ~5,000 services with ~2,000 engineers "10 years ago" (host's recollection; treat as approximate) and **~4,500–5,000 services today**, "well-sized" rather than micro.
- Today: about the same number of services as 2019 while the business is ~**10× larger** [POD][SN]; one single global tech stack across all countries [POD].
- **12 global tech sites** [POD]; Uber has "thousands" of engineers (Orosz: "10,000 plus people" — host, informal).

## Pre-AI foundations [POD unless noted]

- RT-API: abstracted internal services for mobile; REST plus server-to-client push protocol; Node.js → **Go**; still one of the highest-QPS services. Successor naming: **Edge Gateway** (Go; REST, gRPC, webhooks, GraphQL; reliability features; its own capture-replay built on Capri; tags required vs optional dependencies).
- **uOwn**: who owns any service/asset; on-call lookup. 2015: no vendor offered it [SN].
- **M3 / M3DB**: ~**500 million metrics per second** with high cardinality (2015–16 era claim); open-sourced; Chronosphere built on it [SN].
- **Michelangelo**: end-to-end ML platform (features, training, monitoring, serving), hundreds of models; deep-learning parts open-sourced "a couple of months ago" (i.e. ~mid-2026) [POD]; now hosts GenAI/agentic components.
- **Cadence**: durable workflow engine for multi-day flows (driver onboarding, CRM campaigns); open-sourced; Temporal built on its ideas [SN says "built on top of the open sourced Cadence framework"].
- **Morpheus**: feature flags + experimentation, switchback tests, two- and three-sided marketplaces, automatic analysis (p-values, metrics) [POD/SN].
- Cities as first-class: per-city metrics cardinality; some critical platform services **sharded by city**; each city pinned to a region and can fail over across regions at any time; **logical deployment groups** route a group of cities to a group of containers (for some services only) [POD].
- Repos: micro-repos per service, 2–3 build systems and 2–3 test systems → **2017–18** monorepos, **one per language** (Go, Java, iOS, Android, …) [POD]. **Bazel** across all repositories [POD].
- **DevPods** (2017 [SN; Orosz says "being developed in 2017"]): cloud developer boxes, one flavor per monorepo (UI shows Go, Java, Android, Web, Machine learning, Base, plus an "UberOne"(Python) tile); build caches; beefier than laptops; build/test SLAs; Kubernetes clusters on multiple clouds, warmed pools, cloned from pre-built images with repositories and build caches; **seconds** to start; all AI tools pre-installed (Claude Code, Codex, OpenCode); non-engineers use them too; **mega DevPod** with all repositories (cross-repo agent PRs; Minion flavor).
- **Jaeger**: distributed tracing built ~2017–18 [POD], open-sourced; parent/child spans; **baggage** propagated across the call stack; the service mesh reads baggage to route test requests (Slate).
- IDLs: services expose **Thrift** or **Protobuf** contracts in one registry; new services are Protobuf; rewrites usually switch to Protobuf [POD].
- **Deputy** (route production requests to a testing instance) and **Cerberus** (route from a local instance to staging) — older tools, superseded by Slate [POD].
- Design docs, incident management tooling built in-house [POD].

## AI foundations [POD unless noted]

- **Model Gateway**: started late **2023** (after ChatGPT/GPT launches); built as a GenAI product on **Michelangelo**; one OpenAI-compatible and Anthropic-compatible API; teams create a client with a Michelangelo project ID and a caller token; all vendors and open/closed-weight models behind it; **every model request at Uber goes through it**; per-user/per-caller attribution; spend limits per project and user (added "later this year", 2026); audit logging; session traces; billing and cache-hit-rate tracking; future model routing entry point. [SN: 2023 decision that everything AI must be model- and harness-agnostic.]
- **AI Guard**: the first middleware added; run by the security team; ensures no sensitive content is sent back; about **five fine-tuned models** (content, safety policy, comms policy, …) run on **every request and every response** with strict latency guardrails [POD]; [SN] adds it measures latencies and flags slow models/queries.
- **AIFX** (AI Foundations): wrapper over all harnesses (**Claude Code, Codex, OpenCode**); pre-installed on DevPods or installable locally; **personas** with default plugins and skills; centrally managed settings propagated to all users; user settings synced across environments; status line with tips and spend per session/harness; `aifx validate` (inner-loop checks); plugin add updates configs across all harnesses whether in use or not.
- **Spend tiers**: default tier per engineer; near the limit, request the next tier with a simple **manager approval** (ROI conversation, minimal paperwork); spend visible within and across harnesses; separate independent tier for **background coding agents**; "for the right type of work, there is no spend limit" [SN]. **CostCheck** plugin analyzes all sessions, gives personalized tips (context hygiene, model sizing). Token costs reduced **~50% over the last few months** [SN, "as we previously covered"].
- **MCP Gateway**: work started **around April 2025** (after Cursor adoption and the MCP spec, early 2025); built by the **same team as the API/Edge Gateway**; MCP specs **auto-generated from the IDL registry** (Thrift/Protobuf) for any service — request/response schemas, descriptions; then **LLM-optimized descriptions** (some tools were 3,000–4,000 tokens); framework for custom MCPs proxied through the gateway; vendor tools (Google Workspace, Slack, Jira, Linear …) also through it; in the last few months, **every MCP projected as a CLI**; carries user permissions.
- **Agent Skills monorepo** (started early 2026): core skills by central platform teams + team-specific skills; plugins and skills portable across harnesses; one quality gate; auto-installed skill marketplace for everyone; skills use MCP Gateway tools; tool to give tips on improving a skill; in flight: collect harness traces → generate improvement patches; ~**30,000 skill executions per day** "in the last few weeks"; a couple of engineers using AI rewrote all skills to the CLI pattern (installing two plugins could otherwise load six MCPs into context). Some teams keep their own repos.
- **Cortana**: AI assistant built by one engineer in **December 2025**; web, Slack, CLI; answers questions across all repositories; later grounded in the context graph; respects existing user permissions; e.g. 360° health report for a service.
- **Context graph**: **100+ node types, 130+ edge types**, live; nodes for every employee, PR, asset, design doc, feature, on-call event, config change, incident, tables/columns/queries; built with help of the **graph platform team** that runs Uber's production graph (billions of nodes; the context graph is much smaller); agents navigate with Cypher queries; result: quality up, cost and latency down "in a whole bunch of categories of questions" (early).

## Lifecycle [POD unless noted]

- **Design-doc hub** (the transcript's "U-Plan"): PRDs, ERDs (engineering requirements/design documents), launch reviews, XP reviews, production-readiness reviews in one place; status, approvals, owners; Jira/Linear links; fed to the context graph; agentic skills for design docs.
- **Minion**: background coding agent, built **2025** [SN]; **~15% of all production PRs** go through Minion; current iteration **Minion v2**; web and Slack; plan mode or one-shot; "@Minion follow this thread… create a PR" from Slack; on-call uses it in support channels; runs on the **mega DevPod** (all repositories; one or many PRs across repos); started with maintenance tasks; scope grows as self-validation tools are added (web, mobile, backend APIs).
- PR volume up year over year; P50 and P90 cycle time tracked for inner loop (to a green PR) and outer loop (review + CI).
- **CI code red**: CI jobs "doubled or more than doubled" year over year (12 months) → internal code red earlier in 2026 [SN]. Simple CI jobs (linter, coverage rules, build rules, template rules) moved to the inner loop behind **`aifx validate`** [SN writes "afx validate"; use `aifx validate`]. Visual validation: emulator, web, staging deploy. **Self-healing CI** applicable per PR or to all PRs.
- **Code Inbox**: all PRs waiting for you and that you created; needs action / participating; build checks; video; AI review already run; screenshots and videos; **risk score** and **blast radius** being added. All PRs still require a human engineer's review because incident cost is high. Future **green lane** (auto-landing) for some low-risk classes once risk scoring is backtested on years of data: "P0 is first getting all the signals in the right place", auto-landing is P1. Screenshot shows PRs by "shepherd-bot" with tags "[self-healing][code-review-workflows]" and "dead-code-cleanup".
- **Slate**: deploy your branch to your own short-lived instance; pin test-account UUIDs; the rest of the upstream/downstream calls go to shared staging; multi-service tests; routing via Jaeger baggage + service mesh; environments expire (UI shows "2 days left", "19 hours left"); agents use Slate via MCP/CLI ("slate mcp create new slate environment… deploy service"); agent browser A/B on main vs branch → before/after report; screenshots/videos attached to PRs; iOS, Android, web, backend APIs.
- **Capri** (capture replay): for the most complex platforms; one middleware in standardized language frameworks captures inbound and outbound request/responses, including downstream calls; pipeline with rules mapping request fields to dimensions (e.g. marketplace type eats, line of business); generates live combination set → **MatchGuard**, run pre-deploy in CI/CD across the full combination set, before/after (e.g. "cash trips only in Brazil"); replay one captured session on a Slate env (e.g. SF Uber Eats bug); agents can loop fix → replay.
- **Shepherd**: large-scale change platform after the monorepo move; **OpenRewrite** policies for deterministic changes (e.g. signature changes); knows module ownership; one PR per module; AI-based Shepherd for agentic changes (e.g. fix context propagation for tracing); each migration a **campaign** with a YAML policy file (e.g. JUnit 4 → JUnit 5); campaign owner tracks status.
- **Fox**: a few months old; "self-improving code bases"; services enroll into skills (dead code cleanup, performance analysis, noisy logs, …); weekly PR generated **on Sunday** (low CI load); opt-in now, some skills to move to opt-out; maintenance-category PRs analyzed to create/improve skills.
- **Wisdom**: employee dogfooding bug reports from rider/earner beta apps; AI routing to the owning team; logs, telemetry, analytics, network requests, feature flags in one place; repro steps; expected vs observed; screenshot example "Cannot mock location on my device anymore"; tabs Summary / Reproduce / Root Cause Analysis / Fix with an Agent / Log Explorer; replay the reporter's network responses on a test device by bug UID.
- **DebugAssist**: managed agent; root cause, impact, evidence timeline; hand-off to Minion → PR attached to the Jira task with the RCA; corrections feed improvement of DebugAssist and Minion.

## Measurement and role [POD]

- Pre-AI: code throughput, DevEx surveys every few months, NPS/sentiment, incidents per diff, code coverage. Orosz [HOST]: managers looked at diffs per engineer (until 2020).
- Now: from **diff velocity to feature velocity**; all PRs tagged by category (feature, bug fix, maintenance, testing, documentation) and complexity; feature share up, maintenance share down; AI clustering to reconstruct PRD → ERD → task links and compute **P50 feature time** by complexity per half over the last 2–3 years; locate bottleneck phases (PRD, launch, rollout).
- "Capability overhang": models can do more than current harnesses/orchestration let them.
- Role: context engineering; specs and constraints; multitasking across sessions; scoping/tracking/verifying work; spotting code smells; Medisetty does "way more PRs" than last year.
- Customer-support example: runbook → AI-agent policy; APIs, attributes, configuration, manual evals before launch, continuous evals after; now agents draft V0 policies, configuration and testing automated, synthetic evals from past context; "used to take weeks".
