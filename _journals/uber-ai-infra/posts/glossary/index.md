> **IN THIS PAGE, YOU WILL:** Find the book's vocabulary in one place: the terms each chapter owns and defines, the AI-tooling terms the chapters assume (harness, skill, MCP, background agent), Uber's own names and phrases from the episode, and the measurement and evidence labels, each with a short definition and a link to the chapter that explains it.

<br>
The book uses three kinds of vocabulary, and they are easy to mix up. **Uber's own names** (Minion, Slate, Capri, AIFX) come from the October 2026 *Pragmatic Engineer* episode and Uber's written record, and mean what Uber says they mean. **AI-tooling terms** (harness, skill, MCP server, background agent) are industry vocabulary that changed fast between 2024 and 2026; the definitions here are the ones the chapters use. **Terms the book coins or sharpens** (grounding turns, spend tier, standard build contract, AI-ready developer infrastructure) are the author's names for patterns the record describes without naming them. The chapter column says which chapter owns each term; when a chapter and this page disagree, the chapter's worked explanation is the better guide, and one of them needs correcting.

Definitions of Uber systems describe the system as of October 2026, as far as the public record shows. For each system's era, evidence label and dependencies, use the [[system-catalog]]; for the sources behind a definition, follow the chapter to its "Sources and Evidence" section or use the [[bibliography]].

## Terms This Book Defines

Each term below is owned by one chapter, which defines it on first use and treats it in depth. Other chapters use the term in the same sense and link back.

| Term | Definition | Chapter |
| --- | --- | --- |
| **Agent self-verification** | An agent checking its own change end to end before asking a human for review: deploying the branch, exercising it, comparing it with main and attaching the evidence (screenshots, videos, before/after reports) to the PR. | [[slate]] |
| **AI Guard** | The security team's middleware in Uber's Model Gateway: a set of specialized safety and policy models (about five, fine-tuned, in the episode's account) that inspect every request and every response under a strict latency budget. | [[model-gateway]] |
| **AI-ready developer infrastructure** | The book's name for seven auditable properties that let agents work safely: standard builds, ownership metadata, typed contracts, propagated context, ephemeral environments, captured traffic and change campaigns. | [[the-harness-is-the-easy-part]] |
| **AIFX (AI Foundations)** | Uber's layer over every supported coding harness (Claude Code, Codex, OpenCode): it owns personas, settings, plugin and skill distribution and the status line, so the harness itself can be swapped. "AI Foundations" is also the name of the Uber team. | [[aifx-harness-layer]] |
| **`aifx validate`** | The single command behind which Uber put simple CI checks (linter, coverage rules, build rules, template rules) so agents run them in the inner loop before opening a PR. | [[inner-loop-and-self-healing-ci]] |
| **Autonomy ladder** | Six levels of work handed to agents, from assisted interactive use (A0) to a green lane where some low-risk changes land without human review (A5), each gated by minimum readiness scores; the ceiling is set by the lowest required score, not the average. As of October 2026, Uber had reached A4 and not opened A5. | [[the-retrofit-playbook]] |
| **Background agent** | A coding agent that runs unattended in a cloud workspace while the engineer does something else, and delivers a PR rather than an interactive session. Minion is Uber's. | [[minion]] |
| **Build, open-source, buy lifecycle** | The path several Uber platforms took: build in-house when no vendor sells what is needed at Uber's scale, open-source the general part, buy once the market catches up, and keep building only where the need is unique. | [[build-what-does-not-exist]] |
| **Campaign** | One change run across the codebase by Shepherd: defined by a policy file (YAML), delivered as one PR per module routed to the module's owner, and tracked by a campaign owner until it lands. | [[shepherd-and-fox]] |
| **Capri** | Uber's capture-replay system: one middleware in the standard language frameworks records production sessions and their downstream calls, a rules pipeline tags them by dimension, and captured sessions can be replayed against a change. | [[capri]] |
| **CI code red** | The internal emergency Uber declared in 2026 after CI jobs "doubled or more than doubled" in twelve months as agents raised PR volume. | [[inner-loop-and-self-healing-ci]] |
| **City as a domain primitive** | Uber's practice of treating the city as a typed value that every platform layer understands, from metrics and feature-flag rules to service sharding and regional failover. A **domain primitive**, in the book's sense, is the business concept a whole platform is built to understand; elsewhere it may be a tenant, market, store or region. | [[build-what-does-not-exist]] |
| **CLI projection** | Exposing every MCP tool as a command-line call, so an agent invokes tools without loading their schemas into its context; Uber's form is Code Mode (`aifx mcp`). | [[mcp-gateway]] |
| **Code Inbox** | Uber's review queue, which brings together the PRs waiting for an engineer and the signals for each: AI review, build checks, screenshots and videos, and (being added) a risk score and blast radius. | [[code-review-signals]] |
| **Context engineering** | The deliberate selection, construction and delivery of everything an agent sees while it works: instructions, task description, relevant code and documents, tool access, examples and the environment. | [[the-engineer-as-context-builder]] |
| **Context graph** | In Uber's usage, a live graph of the company's engineering metadata (people, services, PRs, design docs, incidents, config changes, tables and queries) with typed edges, kept current from the systems of record and queried by agents as their first step. | [[context-graph]] |
| **CostCheck** | The episode's name for Uber's cost-coaching tool, which analyzes an engineer's sessions and gives personalized tips on context hygiene and model sizing; Uber's August 2026 blog calls it a "cost check skill". | [[token-spend-governance]] |
| **Counter-reading** | The case against transferring Uber's experience: Uber's scale, budget and decade of platform investment are not a typical company's, and the systems that worked are the ones that were described. | [[the-harness-is-the-easy-part]] |
| **DebugAssist** | Uber's managed agent for bug investigation: it proposes a root cause, the impact and an evidence timeline, and hands an agreed root cause to Minion for the fix. | [[wisdom-and-debug-assist]] |
| **Design-doc hub** | The book's name for Uber's planning tool (the transcript's "U-Plan", spelling unconfirmed): one place for PRDs, ERDs and launch, experiment and production-readiness reviews, with status, approvals, owners and ticket links. | [[plans-as-source-of-truth]] |
| **DevPod** | Uber's cloud development environment: a container on Kubernetes started from a pre-built image of one monorepo flavor, with repositories, build caches and AI harnesses already in place. | [[devpods]] |
| **Dimension tagging** | In Capri, the rules pipeline that maps fields of a captured request to business dimensions (such as marketplace type or line of business), so each session says what combination of product, city and payment type it represents. | [[capri]] |
| **Edge Gateway** | Uber's Go API gateway and the successor to RTAPI: the single entry point that authenticates, tags and routes external requests, supporting REST, gRPC, webhooks and GraphQL. | [[contracts-and-context-propagation]] |
| **Feature velocity** | How fast features reach users, measured per feature rather than per diff; Uber's North Star after it moved away from counting diffs. | [[feature-velocity]] |
| **Flavor** | A DevPod image for one monorepo or use, such as Go, Java, Android, Web, ML or Base; the mega DevPod is the flavor with every repository. | [[devpods]] |
| **Foundation→AI dependency map** | The book's table linking each AI-era Uber system to the pre-AI platform it reuses, with the evidence for each link. | [[the-harness-is-the-easy-part]] |
| **Fox** | Uber's continuous-maintenance loop on the Shepherd platform: services enroll in skills such as dead code cleanup, performance analysis and noisy logs, and Fox opens a PR for them every Sunday, when CI load is low. | [[shepherd-and-fox]] |
| **Green lane** | Medisetty's name for a future auto-landing path for low-risk PR classes, to be enabled once risk scoring is backtested on years of data; in the book's sense, a path for PR classes whose backtested risk falls below a threshold. | [[code-review-signals]] |
| **Grounding turns** | The model turns an agent spends discovering which domain, services, data, documents and owners a task concerns before it can act on the task. | [[context-graph]] |
| **Harness-agnostic principle** | The rule, dated in the show notes to Uber's 2023 decision, that nothing built with AI should depend on one coding harness; engineers keep their settings, skills and tools when they switch. | [[aifx-harness-layer]] |
| **IDL registry** | The single place where every service's interface definition (Thrift or Protobuf) can be found; the source from which Uber's MCP Gateway generates tools. | [[contracts-and-context-propagation]] |
| **Inner loop / outer loop** | The **inner loop** is what a developer or agent does before asking anyone else for anything: edit, build, test, look, repeat. The **outer loop** starts when the change is shared: PR, CI, review, merge queue and deployment. | [[inner-loop-and-self-healing-ci]] |
| **Managed agentic loop** | Medisetty's phrase for a recurring, centrally run agent task that opens PRs for enrolled services, as Fox does. | [[shepherd-and-fox]] |
| **MatchGuard** | Uber's pre-deploy check in CI/CD that runs a change against the full set of live combinations derived from Capri captures and compares before and after. | [[capri]] |
| **MCP Gateway** | Uber's gateway for every internal service and vendor tool exposed to agents: it generates tools from the IDL registry, keeps them disabled until owners enable them, checks the caller's permissions per tool and projects the catalog as a CLI. | [[mcp-gateway]] |
| **Mega DevPod** | The DevPod flavor that holds all of Uber's repositories, so an agent such as Minion can make PRs across them. | [[devpods]] |
| **Meta-shift** | The change in the engineer's output from building software to building the systems that build and verify it: captured principles, tools, evaluations and human checkpoints. | [[the-engineer-as-context-builder]] |
| **Minion** | Uber's background coding agent, started from the web or Slack, run on the mega DevPod, and stopping at a draft PR; around 15% of production PRs, in the episode's account. | [[minion]] |
| **Model Gateway** | The internal service through which every model request at Uber goes: OpenAI- and Anthropic-compatible APIs over many vendors and open-weight models, with AI Guard, attribution, audit logs, session traces and spend controls. | [[model-gateway]] |
| **Model-agnostic principle** | The rule that no product or tool at Uber should depend on one model vendor's API, keys or SDK; every call goes through the Model Gateway instead. | [[model-gateway]] |
| **Per-language monorepo** | One repository per language or platform (Go, Java, iOS, Android and others) that holds all of that language's code, which Uber moved to in 2017–2018. | [[monorepos-and-one-build]] |
| **Persona** | In AIFX, a named role profile that decides which plugins and skills an engineer gets by default. Uber has not listed its personas. | [[aifx-harness-layer]] |
| **PR type tagging** | Classifying every PR by type (feature, bug fix, maintenance, testing, documentation) and complexity, so the PR mix and feature time can be measured. | [[feature-velocity]] |
| **Readiness assessment** | The playbook's scoring of an organization on twelve properties from 0 (absent) to 3 (measured, near universal, queryable by agents): the seven AI-ready foundation properties plus five AI-layer controls. The scores gate the autonomy ladder. | [[the-retrofit-playbook]] |
| **Retrofit playbook** | The book's order of operations for a company that must build the foundations and the AI layer at the same time: readiness assessment, autonomy ladder, sequence by company size, a 12-month roadmap and anti-patterns. | [[the-retrofit-playbook]] |
| **Risk score** | A per-PR estimate of how likely a change is to cause harm, shown to the reviewer in Code Inbox; Uber was adding it as of October 2026. | [[code-review-signals]] |
| **Self-healing CI** | Agents that repair CI failures on a PR, applied per PR or to all PRs; at Uber, one of the tasks of managed agents. | [[inner-loop-and-self-healing-ci]] |
| **Shepherd** | Uber's large-scale change platform: deterministic OpenRewrite changes or agentic prompts and skills, delivered as per-module PRs to owners and tracked as campaigns. | [[shepherd-and-fox]] |
| **Skill quality loop** | The cycle of gating, distributing, observing and improving skills after their first version; at Uber, started but not finished as of October 2026. | [[skills-monorepo]] |
| **Skills monorepo** | Uber's single repository for core platform skills and team skills, with one quality gate, portability across harnesses through AIFX and an auto-installed marketplace. | [[skills-monorepo]] |
| **Slate** | Uber's Short-Lived Application Testing Environment: a per-developer or per-agent environment that deploys a branch of one or more services and routes only pinned test accounts to it; two-day default lifetime. | [[slate]] |
| **Spec as hand-off** | A plan reaching an explicitly marked state in which an agent may start executing it, such as the "Ready for Minion" status in Uber's planning demo. | [[plans-as-source-of-truth]] |
| **Spend tier** | A per-engineer spending allowance for a period, one of several levels, that the engineer moves up with a lightweight manager approval rather than hitting a fixed cap. | [[token-spend-governance]] |
| **Standard build contract** | A guarantee that any module can be built, tested and linted with the same small set of commands from a known environment, with results that do not depend on whose machine runs them. | [[monorepos-and-one-build]] |
| **Standardized language frameworks** | The shared libraries every service in a language starts from (server, RPC clients, configuration, logging, metrics, tracing, middleware hooks), so behavior added to the framework reaches the whole fleet. | [[contracts-and-context-propagation]] |
| **Test-account pinning** | Associating specific test riders, drivers or profiles (by UUID) with a Slate environment, so only their requests reach the branch build and everyone else stays on the shared fleet. | [[slate]] |
| **Trace baggage routing** | Steering requests by key–value data carried in the trace context: at Uber, a tenancy value in Jaeger (later OpenTelemetry) baggage tells the Edge Gateway and the routing agents to send a test request to a branch build. | [[contracts-and-context-propagation]] |
| **Wisdom** | Uber's dogfooding bug-report system for beta apps: reports arrive routed to the owning team with logs, analytics, network requests, feature flags, reproduction steps and expected versus observed behavior. | [[wisdom-and-debug-assist]] |

## AI-Tooling Terms

Industry terms the chapters use without re-deriving them. The chapter column points to where the book discusses the term most fully.

| Term | Definition | Chapter |
| --- | --- | --- |
| **Actor-chain token** | A short-lived credential that records the chain of identities in a call (the user, the agent acting for them, the service), so each hop can be authorized against the human's own permissions. | [[mcp-gateway]] |
| **Agent browser** | A browser driven by an agent, used to exercise a web or mobile-web change; in Uber's flow, run against main and against the branch to produce a before/after report. | [[slate]] |
| **Agent Skills** | An open format, introduced by Anthropic in October 2025, in which a skill is a folder with a `SKILL.md` file of instructions plus optional scripts and reference files. | [[skills-monorepo]] |
| **AGENTS.md / CLAUDE.md** | Instruction files at the top of a repository (or a folder) that tell coding agents how to build, test and work in it; AGENTS.md is the open format, CLAUDE.md the Claude Code equivalent. | [[monorepos-and-one-build]] |
| **Auto-landing** | Merging a PR without a human approval once automated gates pass; Uber's planned form is the green lane. | [[code-review-signals]] |
| **Capability overhang** | Medisetty's term for model ability that current harnesses, tools and orchestration do not yet put to use. | [[feature-velocity]] |
| **Code Mode** | Uber's name for MCP tool use through the `aifx` CLI instead of loaded MCP schemas; the company default for coding agents as of October 2026. | [[mcp-gateway]] |
| **Coding agent** | A model running in a loop with tools (file edits, shell commands, searches) to complete a software task, interactively or in the background. | [[minion]] |
| **Confused deputy** | A security failure in which a privileged component (such as a tool server) is tricked into acting with its own authority on behalf of a caller who lacks it. | [[mcp-gateway]] |
| **Context window** | The fixed amount of text (in tokens) a model can consider at once; tool schemas, instructions and history all compete for it. | [[mcp-gateway]] |
| **Cypher** | A graph query language; agents navigate Uber's context graph with Cypher-like queries, much as they navigate files with bash. | [[context-graph]] |
| **Draft PR** | A pull request marked not ready for merge; Uber's Minion stops at a draft PR with a table of the checks it ran. | [[minion]] |
| **Eval (evaluation)** | A repeatable test of an AI system's output against expected behavior; **synthetic evals** are generated from past cases rather than written by hand. | [[the-engineer-as-context-builder]] |
| **Harness** | The agent program an engineer runs, such as Claude Code, Codex or OpenCode: it owns the model loop, the tools and the user interface. | [[aifx-harness-layer]] |
| **LLM-optimized tool description** | A tool description rewritten for a model to choose and call the tool correctly, shorter and clearer than the raw schema comments; Uber found some generated tools ran to 3,000–4,000 tokens. | [[mcp-gateway]] |
| **Managed agent** | An agent session started by a system rather than a person (self-healing CI, Fox, DebugAssist), with human review or escalation and its cost tracked by outcome. | [[inner-loop-and-self-healing-ci]] |
| **MCP (Model Context Protocol)** | An open protocol, introduced by Anthropic in November 2024, through which agents discover and call tools exposed by **MCP servers**. | [[mcp-gateway]] |
| **Model routing** | Choosing which model serves a request by task, cost or latency; positioned at Uber as a future job of the Model Gateway. | [[model-gateway]] |
| **Omni MCP** | Uber's single proxy server that exposes the whole tool catalog through four discovery and invocation tools, so agents load schemas only when needed. | [[mcp-gateway]] |
| **One-shot** | Giving an agent one prompt and letting it execute without a reviewed plan, suitable for simple tasks. | [[minion]] |
| **Open-weight model** | A model whose weights are published, so it can be hosted in-house; Uber's Model Gateway serves both open-weight and closed models. | [[model-gateway]] |
| **Plan mode** | A mode in which the agent first proposes a plan for the engineer to review, then executes it. | [[minion]] |
| **Plugin** | A packaged bundle of skills, commands, hooks or MCP configuration for a harness; through AIFX, one `plugin add` installs it in every harness. | [[aifx-harness-layer]] |
| **Progressive disclosure** | Loading a skill's short metadata up front and its full instructions only when the task needs them, to save context. | [[skills-monorepo]] |
| **RAG (retrieval-augmented generation)** | Answering from documents retrieved at query time; Uber's 2024 Genie copilot worked this way. | [[context-graph]] |
| **Response projection** | An MCP Gateway feature in which the model lists the response fields it needs and the gateway trims the response to them. | [[mcp-gateway]] |
| **Session trace** | The recorded sequence of prompts, model turns and tool calls in one agent session; Uber reads them to find grounding turns and to improve skills. | [[context-graph]] |
| **Skill** | Packaged instructions and scripts that an agent loads on demand when a task matches the skill's description. | [[skills-monorepo]] |
| **Spec-driven development** | Writing a specification first and having agents plan and implement from it, as in GitHub's Spec Kit (2025). | [[plans-as-source-of-truth]] |
| **Status line** | A line in the harness interface; at Uber, AIFX uses it for tips and for spend within the session, the harness and across harnesses. | [[aifx-harness-layer]] |
| **Subagent** | A secondary agent session started by a main agent for a bounded task, often on a cheaper model. | [[token-spend-governance]] |
| **Token** | The unit models read and write and vendors bill by; token cost per session is the unit Uber's spend governance tracks. | [[token-spend-governance]] |
| **Tool poisoning** | An attack that hides instructions in a tool's description so the agent follows them; named by Invariant Labs in April 2025. | [[mcp-gateway]] |

| **P0 / P1** | Priority labels: Medisetty called getting review signals in place P0 and the green lane P1. | [[code-review-signals]] |
| **P50 feature time** | The median time from product spec to rollout for features of one complexity class, computed per half-year. | [[feature-velocity]] |
| **Platform/program split** | Uber's 2014 reorganization into program teams that build products and platform teams that build shared infrastructure. | [[build-what-does-not-exist]] |
| **Production PR** | The episode's unit for Minion's share ("around 15% of all of the production PRs"); not defined publicly, and different from "merged PRs" or "PRs attributed to agents". | [[minion]] |
| **Service tier** | Uber's criticality rating for services, 0 (most critical) to 5; large monorepo changes roll out from tier 5 to tier 0. | [[code-review-signals]] |
| **SUT (service under test)** | A service deployed from a branch into a Slate environment; other calls go to the shared fleet. | [[slate]] |

| **Tenancy** | A tag attached to a request at the edge and propagated through every service, marking it as production or test (and which test environment). | [[contracts-and-context-propagation]] |

## Engineering, Measurement and Evidence Terms

| Term | Definition | Chapter |
| --- | --- | --- |
| **Baggage** | Key–value data carried with the trace context through every hop of a request; trace context records what happened, baggage lets infrastructure change what happens. Standardized by the W3C. | [[contracts-and-context-propagation]] |
| **Bazel** | Google's open-source build system with hermetic, cached builds; Uber uses it across all its repositories. | [[monorepos-and-one-build]] |
| **DORA** | Google's DevOps Research and Assessment program; its 2025 report found AI amplifies an organization's existing strengths and dysfunctions. | [[the-harness-is-the-easy-part]] |
| **DX Core 4** | A productivity framework from DX measuring speed, effectiveness, quality and business impact. | [[feature-velocity]] |
| **ERD** | Engineering requirements or design document: the engineering plan for a PRD. | [[plans-as-source-of-truth]] |
| **FinOps** | The practice of managing cloud (and now AI token) spend with shared visibility and unit economics. | [[token-spend-governance]] |
| **Large-scale change (LSC)** | Google's term for a change across many parts of a codebase, split into owner-sized pieces; Uber's equivalent runs as Shepherd campaigns. | [[shepherd-and-fox]] |
| **Merge queue** | A system that tests and lands changes in order so the main branch stays green; Uber's is SubmitQueue, which speculates on combinations of pending changes. | [[monorepos-and-one-build]] |
| **METR study** | METR's 2025 trial in which experienced developers were 19% slower with AI while believing they were 20% faster; its 2026 follow-up was judged unreliable. | [[feature-velocity]] |
| **OpenRewrite** | An open-source framework of recipes that transform code over lossless syntax trees; Shepherd uses it for deterministic changes. | [[shepherd-and-fox]] |
| **OpenTelemetry** | The open standard for traces, metrics and logs; Uber's routing overrides moved to OpenTelemetry baggage by 2024. | [[contracts-and-context-propagation]] |
| **P50 / P90** | The median and 90th-percentile values of a distribution, such as cycle time. | [[inner-loop-and-self-healing-ci]] |
| **PRD** | Product requirements document: the product spec for a feature. | [[plans-as-source-of-truth]] |
| **Protobuf / Thrift** | Interface definition languages for service contracts; Uber's services expose one or the other, and new services use Protocol Buffers. | [[contracts-and-context-propagation]] |
| **RCA** | Root cause analysis. | [[wisdom-and-debug-assist]] |
| **Service mesh / sidecar** | Infrastructure that carries service-to-service traffic through a proxy next to each service; Uber's sidecar is Muttley. | [[contracts-and-context-propagation]] |
| **SPACE** | A 2021 framework that measures developer productivity across satisfaction, performance, activity, communication and efficiency. | [[feature-velocity]] |
| **Evidence labels** | The book's markers for the source of a statement: **POD** (the episode), **SN** (Orosz's show notes), **HOST** (Orosz's own recollection), **DOC yyyy** (a dated Uber source), **IND yyyy** (an industry source), **PRESS yyyy** (press reports), plus **INFERENCE, NOT DOCUMENTED** for the author's labeled inferences. | [[introduction]] |
