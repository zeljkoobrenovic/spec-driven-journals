# Editorial review: Glossary

Reviewed 14 September 2026. Read the complete glossary and compared its definitions with their use in the chapters.

## Overall assessment

This is a useful reference for technology leaders learning finance and ownership vocabulary. Grouping terms by learning sequence is sensible, and many definitions actively prevent common mistakes: commitment versus cash, manager versus fund, enterprise versus equity value, operating earnings versus cash, and percentage versus percentage point.

Its main weaknesses are retrieval and density. Several rows combine three or more distinct concepts, and a few broad teaching definitions need narrower wording. It also contains remnants of a support-service design frame that the current book does not develop.

## Detailed feedback

- **Organization and lookup:** The thematic order supports a complete reading, but relying on the browser's Find function makes an unfamiliar acronym harder to discover. Add a short alphabetical index of terms and abbreviations linking to sections or entries. Keep the thematic explanations underneath.
- **Clarity and pacing:** Rows such as “Preferences / dilution / leaver provisions,” “AI / generative AI / inference” and “SaaS / IT / IP” compress unrelated distinctions into one cell. Pair close contrasts such as gross/net return; separate independent concepts so each is readily findable.
- **Consistency:** “Engagement sponsor” correctly allows either company or investment-firm representation, while the engagement chapter and Tool 4 narrow the role to the investor. Use this glossary definition as the general rule and label the specific investor role explicitly. Similarly, differentiate broad work lead time from DORA's defined change lead time in the delivery chapter.
- **Confirmed overnarrow definition:** The AI entry describes AI as software performing tasks from learned patterns. That describes a major class of current systems but excludes knowledge-based approaches covered by the [OECD's explanatory definition](https://www.oecd.org/content/dam/oecd/en/publications/reports/2024/03/explanatory-memorandum-on-the-updated-oecd-definition-of-an-ai-system_3c815e51/623da898-en.pdf). Either broaden the definition or say the book mainly discusses learning-based AI.
- **Technical distinctions worth preserving:** The glossary explicitly avoids treating private share ownership as freedom from reporting obligations, explains EBIT's limits as a synonym for operating profit, and gives Visma's actual ARR meaning. These are better qualified than some chapter headings and source notes. Preserve them as the collection's terminology standard.
- **Concern needing qualification:** “Asset / liability” is an intentionally informal pair, not a full accounting recognition definition. Keep it labelled as a teaching description rather than expanding into a technical accounting standard. Likewise, avoid suggesting all microservices are automatically independently operable merely because the architectural goal is separate deployment.
- **Scope and conclusion:** “Productscapes / accelerator” names a proposal that is not explained in the current core chapters; the toolkit's optional-appendix reference is also orphaned. Remove this entry from the reader's core vocabulary unless it has an actual use and destination. The final durable-value definition is a good endpoint because it identifies the author's proposed standard instead of claiming an accounting meaning.

## Recommended changes

- **High impact — Establish and apply a collection-wide terminology sheet.** Start with investor/manager/fund, shareholder versus accountable leader, investor-side sponsor, commitment versus cash, earnings measures, and financial versus causal contribution. Correct contradictions in the chapters rather than weakening the glossary's better distinctions.
- **Medium impact — Split overloaded rows and add alphabetical access.** Preserve thematic grouping, which is useful for beginners; improve lookup without turning the page into a second textbook.
- **Medium impact — Broaden or qualify AI.** For example: “AI systems use computational models, including learned or knowledge-based approaches, to generate outputs such as predictions, content or decisions.” Define generative AI and model inference in separate entries.
- **Medium impact — Remove unsupported scope remnants.** Productscapes belongs in the bibliography as provenance if it influenced the work; it does not need to be a reader-facing concept without a substantive application.
- **Low impact — Add targeted chapter links beside easily confused terms.** Useful candidates are cash conversion, conditional commitment, adjusted EBITDA and retained investment value. Avoid repeating a citation in every row where one section-level source already suffices.

## Proposed structure

Short use instructions → alphabetical term/abbreviation index → existing thematic sections with smaller entries → author's evaluative terms. No major conceptual rewrite needed. The reference's precision is a strength; the main task is to make it easier to retrieve and consistently apply.
