# Spec: The Competent Software Engineer

> Working doc for the post in this folder. The spec drives the post; the post
> is the artifact.

## Intent

State the baseline I hold every software engineer to at the first career
stage, and how I coach it — grounded in the Competent Software Developer
chapters of Gergely Orosz's *The Software Engineer's Guidebook*. The
load-bearing idea: competence is reliably getting the right things done —
know and deliver the week's top priority, notice within 30–60 minutes that
you are blocked and act, break work into shippable pieces, estimate honestly
— with craft (readable defensive code, debugging, everyday refactoring,
testing as part of development, mastered tools) underneath, and growth run
through mentors, goodwill, and a weekly self-review. The article is in the
manager's voice (expectations and coaching); the Checklist tab is the
checklist I hand the engineer, in the engineer's voice.

## Audience

Engineers at the first career stage (so they know the bar and own it);
managers and tech leads in my organization who coach against this baseline;
peer executives comparing ladder expectations. First-person declarative.

## Success criteria

- [x] **Principle is quotable** — highlight states that competence is
      reliably getting the right things done, names both layers (delivery
      habits and craft), and says both are learnable and explicitly coached.
- [x] **The delivery habits survive** — top priority named, confirmed, and
      delivered; the 30–60 minute blocked rule with the self-service
      repertoire before asking for help; work broken into shippable pieces
      with edge cases separated; estimates anchored, worst-cased under
      uncertainty, and updated.
- [x] **The craft layer survives** — readable code per team conventions,
      defensive code (validate inputs, malicious external input, safe
      defaults), root cause before fixing, refactoring as an everyday habit
      with safety nets, testing before review with regression tests.
- [x] **The growth loop survives** — mentors (dedicated, ad hoc, internet),
      goodwill mechanics, initiative only after expected work, and the
      nine-question weekly self-review closing the checklist.
- [x] **Voice split holds** — article in the manager's voice; checklist in
      the engineer's first person.
- [x] **Credit is explicit** — References name Gergely Orosz, *The Software
      Engineer's Guidebook* (Pragmatic Engineer, 2023), and the chapters distilled.
